Thuật toán Lock Redis SETNX (10m TTL)

Bảng Hướng Dẫn Kiểm Thử (Sprint 08 — Idempotency)

1. Chống bấm đúp (Double-Submit Prevention):

Mỗi khi bắt đầu tạo lệnh, Angular tự động tạo 1 UUID v4 trong Header X-Idempotency-Key.

2. Thử nghiệm Gửi trùng Request:

Sau khi chuyển tiền thành công, bấm nút "🔁 Gửi lại với CÙNG Idempotency Key". Backend sẽ bắt được key trong Redis và trả về kết quả Cached mà KHÔNG trừ thêm tiền lần 2!

3. Khóa đồng thời (Distributed Lock):

AOP Aspect @Idempotent dùng lệnh SETNX trên Redis để từ chối các request trùng lắp đang chạy song song.
